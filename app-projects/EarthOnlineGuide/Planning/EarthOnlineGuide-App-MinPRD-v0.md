## 2. 产品定义

**首批用户：**已关注或认同“地球Online”叙事、希望从手机获得轻量现实行动提示的中文 iPhone 用户。不是医疗/心理治疗用户，也不是任务投稿社区用户。

**触发场景：**用户主动打开 App 查看当天自动生成的任务，或在其明确开启提醒后收到本地通知。

**一句话定位：**把账号自有的“现实世界游戏任务”节奏，变成用户可在本机勾选完成和回看的每日小任务。

**唯一核心闭环：**当地 `05:00` 自动生成任务 → 用户打开/由通知唤起 → 勾选已完成的单项任务并立即记录时间 → 获得即时反馈 → 可在当天撤销 → 已完成项进入历史 → 次日继续使用。

### 页面与状态

| 页面 | 必须状态 | 首版行为 |
|---|---|---|
| 首次启动 | 未设置 ID / 输入校验失败 / 已设置 ID | 首屏固定文案为“欢迎来到地球Online / 请设置你的ID”。ID 仅保存在本机，允许修改；长度 2–16 个字符，不允许纯空格。首次启动不申请通知权限。 |
| 今日任务 | 普通、彩蛋出现、部分完成、全部核心任务完成、当天撤销、无可用任务 | 每天直接展示 3 个核心任务全文；彩蛋任务按 25% 概率出现。每项可独立勾选和撤销，不设领取、任务详情或“完成当天任务”按钮。 |
| 完成反馈 | 单项完成 / 全部核心任务完成 | 单项完成显示短像素动画与行内反馈；全部核心任务完成后在页首显示“今日核心任务已全部记录”，但不创建“整日完成”记录，并取消当日待处理的 `20:00` 提醒。 |
| 历史 | 空状态 / 已完成记录 / 只读详情 | 只显示已完成任务及完成时间，支持“全部 / 核心任务 / 彩蛋任务”筛选；点击记录进入只读详情。当日撤销后移除对应记录，未完成任务不展示。 |
| 设置 | ID、通知状态、语言、固定主题、固定刷新时间 | 通知只在用户于设置中主动开启后申请；拒绝后提供前往系统设置。主题固定且不显示主题切换入口；刷新时间只读显示“每日05:00”。不提供“删除所有数据”入口；卸载 App 即删除本机数据。 |

### 任务类型与规则

| 类型 | 首版定义 | 决策 |
|---|---|---|
| `CoreTask` 核心任务 | 每个业务日自动生成 3 个，每项独立完成。 | **首版投放**。 |
| `EggTask` 彩蛋任务 | 每个业务日以 25% 概率出现的独立选做任务。 | **首版投放（本地确定规则）**。不可依赖社交评论或投稿。 |
| `Special` 特别任务 | 有明确主题/活动感的限时任务。 | **仅预留数据类型，首版不投放**。 |
| `Emergency` 紧急任务 | 优先级较高的限时任务。 | **仅预留数据类型，首版不投放**；原账号规则 UNKNOWN。 |
| `DLC` | 命名为主题内容包，例如“宠物系统/友谊系统”。 | **仅预留数据类型，首版不投放**；不售卖、不商城、不 IAP。 |

**刷新、完成与随机规则：**

- 以设备当前时区为准，每天当地 `05:00` 进入新业务日并自动生成 3 个核心任务；时区变化当天不重抽，下一业务日生效。
- 用户勾选某一任务即完成并记录本地时间与 UTC 时间；同一业务日内允许取消勾选并撤销完成。
- 跨过下一个当地 `05:00` 后，上一业务日记录锁定；未完成任务直接结束，不进入用户可见历史。
- 不提供领取、跳过、“完成当天任务”或前台换任务。“换一个”只可预留不可触发的内部扩展接口。
- 彩蛋任务以 25% 的本地确定性概率出现；同一用户同一天重启 App，结果不得变化。
- 当天任务一经展示保持固定；未完成任务在下一个业务日起重新进入候选池。已完成且未撤销的核心或彩蛋任务在之后 30 个业务日内不得再次出现，冷却结束后重新进入候选池；未完成任务仍不进入历史页。
- 默认通知为当地 `09:00`“今日任务已刷新”和 `20:00`“仍有任务未完成”；通知是提醒，不是任务生成或完成真值。
- 当天 3 个核心任务全部完成时取消当日 `20:00` 提醒；若用户在 `20:00` 前撤销任一核心任务，应按幂等规则恢复该提醒。
- 首版不包含背景音乐或音效。

### 已冻结的内容与交互规格

- 任务全文直接显示在 Today 卡片中，不设置任务详情页；正文采用一句话，中文尽量不超过 15 个汉字。
- 用户界面只显示“核心任务 / 彩蛋任务”，不展示安全标签、语义分类或其他内部运营分类。
- 当前首版原始内容源为 [EarthOnlineGuide-App-TaskCatalog-Source-v0.md](./EarthOnlineGuide-App-TaskCatalog-Source-v0.md)：166 条核心/日常任务、56 条彩蛋任务，共 222 条记录。
- 上述清单是原始内容源，不等于发布白名单；涉及安全、健康、隐私、不适当互动或平台依赖的任务暂停投放，须经审核、必要改写和用户确认后才能进入 App 任务包。
- 现有 166 条核心任务可供开发和流程测试；正式上线前由用户继续完善任务量，并以 TaskPack Validator 对全部已审核、可投放任务执行 30 个业务日完成冷却、彩蛋概率、体验分散和候选不足模拟。用户计划后续提供约 1000 条任务清单。
- 完成反馈使用短像素动画与行内文案；撤销在同一业务日内立即生效，不展示跳过或替换入口。
- App 默认跟随系统语言；非中文系统默认显示英文，并允许用户在设置中手动切换。语言切换不改变任务抽取和状态。

## 4. 最小数据与状态模型

| 模型 | 最小字段与职责 |
|---|---|
| `TaskPack` | `packKey, packID, contentVersion, formatVersion, selectionPolicyVersion, minimumAppVersion, supportedLocales, checksum, status`；内置内容的唯一发布单元，状态为 imported / validated / active / retired。 |
| `TaskCard` | `cardKey, canonicalTaskID, taskRevisionID, packKey, localizedContent[zh-Hans/en], type, availability, completionRule, feedback, assetRefs, safetyTags, experienceFamilyKey, releaseStatus`；完整审核状态保留在任务内容源和 Validator 清单中，发布 App 只导入精简的 approved / blocked / retired 状态。 |
| `CoreTask` | `TaskCard` 的核心任务变体；每个业务日生成 3 个独立任务实例。 |
| `EggTask` | `TaskCard` 的可选变体，按 25% 的本地确定性概率生成。 |
| `TaskType` | `core, egg, special, emergency, dlc`；类型不自行推导业务规则。 |
| `DailyPlan` | `planKey, installID, businessDayKey, businessDaySequence, timezoneID, startAtUTC, refreshAtUTC, packKey, algorithmVersion, lifecycleState, expectedCoreCount, expectedEggCount, firstPresentedAtUTC`；同一安装同一业务日唯一，作为当天完整任务集合的聚合根。 |
| `DailyInstance` | `instanceKey, planKey, slotKey, canonicalTaskID, taskRevisionID, packKey, taskTypeSnapshot, taskSnapshot, lifecycleState, assignedAtUTC`；属于一个 DailyPlan，保存不可变双语 TaskSnapshot。 |
| `Completion` | `completionKey, instanceKey, canonicalTaskID, completedAtLocal, completedAtUTC, revokedAtUTC, updatedAtUTC, lastMutationID`；完成事实的唯一真值，当业务日内取消勾选则写入撤销时间；再次完成复用记录并更新为最近一次有效完成时间。 |
| `EngineState` | `singletonKey, currentPlanKey, lastBusinessDaySequence, lastReconcileAtUTC, latestClosedBoundaryUTC`；防止时间回拨重新开放旧业务日，并协助恢复当前 DailyPlan。 |
| `NotificationSchedule` | `scheduleKey, businessDateKey, kind, notificationID, scheduledForUTC, status, authorizationSnapshot`；不代表系统一定投递，也不改变任务状态。 |
| `ContentAsset` | `assetKey, id, version, ownerScope, licenseStatus, provenance, checksum, localPath, usageScope`；重新生成资产与字体均须许可/来源可追溯。 |

**唯一真值源与离线：**SwiftData 本机持久化的 `TaskPack + TaskCard + DailyPlan + DailyInstance + Completion + EngineState` 是用户体验真值；DailyPlan 负责当天完整性，Completion 负责完成事实，不建立独立 SelectionLedger。通知只是边缘适配器。首版离线优先：内置任务包、勾选完成、当日撤销和历史均无需账户或网络。

**版本/更新：**首版只读随 App 发布的本地任务包；新包必须完整验证后才能启用，且只影响下一个尚未生成的业务日。已生成 DailyPlan、TaskSnapshot、完成状态与历史不受更新、退役或文案修订影响。网络内容更新、远程开关与 A/B 测试延后。

### 领域不变量与任务包放行

1. 同一安装同一业务日只存在一个完整 DailyPlan；Today 不展示部分生成的计划。
2. DailyPlan 一经展示不得因重启、语言切换、任务包或 App 更新而重抽。
3. TaskSnapshot 在生成后不可变；历史只读取快照，不读取活 TaskCard。
4. DailyInstance 只保存 `active / closed / withdrawn` 生命周期；是否完成只由未撤销 Completion 判断，避免双真值。
5. `canonicalTaskID` 是具体任务的跨版本身份，`taskRevisionID` 是文案修订，`experienceFamilyKey` 是相似体验族。
6. 未完成任务下一业务日重新获得抽取资格；完成且未撤销任务按 canonicalTaskID 冷却 30 个业务日。当天撤销后，该任务不再具有完成冷却资格。
7. 同一 DailyPlan 的核心任务优先来自不同 experienceFamilyKey；近期相似体验只降低权重，候选不足时可以放宽，但安全、许可和完成冷却不得放宽。
8. 首版不实现 SelectionLedger、Completion 事件链、SelectionReceipt、AI 聚类、远程任务包或完成率个性化。
9. TaskPack Validator 必须检查：唯一 ID、版本、双语字段、空文案、任务类型、安全/许可、体验族、资源引用、候选容量、固定种子确定性和升级后既有计划不变。开发校验可把英文缺失记录为发布阻断而继续中文本地测试；发布校验中任一硬检查失败，任务包不得进入 release-eligible active。
10. 任务内容源必须记录：`contentStatus = draft / reviewing / approved / blocked / retired`、`safetyStatus = pending / passed / blocked`、`localizationStatus = zh-ready / en-ready / release-ready`、`licenseStatus = pending / verified / blocked`。发布包只允许导入四项均满足发布条件的任务。
11. DailyPlan 在内存中完成全部抽取与完整性校验后一次显式保存；生成、校验或保存失败时不展示半成品，并以相同业务日、任务包、算法版本和种子重试。不得通过更换 seed、放宽硬约束或调用未审任务“修复”。
12. 若启动时发现不完整 DailyPlan：在 `firstPresentedAtUTC == nil` 且没有 Completion 时，允许删除该可重建半成品并用相同种子重建；若已展示、存在 Completion 或无法证明未展示，则不得自动删除，进入可解释恢复状态。
13. Task Selection fallback 固定为：保持内容批准/安全/许可/类型/明确可用条件/同日 canonicalTaskID 唯一/完成后30业务日冷却 → 放宽近期 experienceFamilyKey 软降权 → 放宽同日体验族分散 → 仍不足时少展示或显示任务包不足。任何时间或 availability 硬条件不得作为 fallback 放宽。
14. `installID` 在用户首次成功设置本地显示 ID 时生成随机 UUID，只保存在 SwiftData LocalProfile。App 重启、升级和修改显示 ID 不改变它；卸载后重装生成新 installID。首版不使用 Keychain、UserDefaults、账号或云端保存 installID。

**恢复/删除：**首版不提供“删除所有数据”入口；卸载 App 会永久失去本机 ID、当天任务、历史、抽取台账与提醒。数据损坏时不得静默清库：先重试打开与校验，失败则进入恢复界面，由用户明确确认后才能重建本地数据。首版不承诺跨设备恢复。

完整唯一键、关系、删除、迁移、随机、业务日与恢复规则以 [EarthOnlineGuide-App-TechnicalArchitecture-v0.md](./EarthOnlineGuide-App-TechnicalArchitecture-v0.md) 为准。

## 7. 用户可见验收标准与首版 App 范围

### 用户可见验收标准

1. 用户在离线状态可看到当地 `05:00` 自动生成的 3 个核心任务；每项均可独立勾选。
2. 用户勾选某项后，该项立即记录完成时间并进入历史；同一业务日内取消勾选后，记录从历史移除。
3. 用户拒绝通知后仍能完成完整闭环；授权后只在当地 `09:00` 与 `20:00` 提醒，点击通知不会直接改变完成状态。
4. 彩蛋任务每天以 25% 的本地确定性概率出现，不需评论、投稿、账号或网络。
5. History 只显示已完成任务，支持全部/核心/彩蛋筛选和只读详情；设置页显示固定 `05:00` 刷新时间，不提供“删除所有数据”入口。
6. App 首次启动不请求通知；只有用户在设置中主动开启后才申请权限，拒绝不影响核心任务功能。

### 首版 App

- 本地任务包读取与版本钉住；每个业务日 3 个核心任务，25% 概率出现 1 个彩蛋任务；特别/紧急/DLC 只预留类型，不投放。
- 首次设置本地 ID、Today 任务全文、短像素完成反馈、历史只读详情与筛选、设置页面及完整状态机。
- 首批 Spike：本地通知、当地 `05:00` 跨日、离线/重启恢复；每项通过后才纳入对应承诺。
- 从工程第一天支持 `zh-Hans` / `en` 数据结构和界面键；开发阶段可先填中文任务，正式发布前必须补齐全部英文任务、英文界面、像素英文字体及许可/回退/无障碍验收。
- 分别留存代码、Build、Test、Simulator、真机和用户证据；设计 10–20 人 C/R 小样本验证，但不把自报完成夸大为现实验证。

### 明确延后

账号系统、云同步、商城/IAP、付费 DLC、公开社区、评论区投稿、任务审核、私信、复杂 AI、个性化推荐、持续定位、地图追踪、照片/视频上传、音频、未获许可的字体/插件、锁屏内联完成、快捷指令完成、Widget 写入、Reminders 写入、后台刷新驱动真值、未经授权的第三方模仿素材、医疗或心理健康主张、远程签名任务包与远程任务运营后台。

## 8. 放行结论

文档层已达到：**可创建工程底座**。这不代表已授权创建，也不代表工程、构建、测试、模拟器、真机或用户验证通过。

创建工程后的首要顺序：领域与持久化最小底座 → `05:00` 跨日 Spike → 离线/重启恢复 Spike → 本地通知真机 Spike → UI/字体/双语验收。任一硬门 FAIL 时停止扩展功能并先修正底座。

不可宣称：项目已经开始、已能构建、已复刻原账号全部流程、已证明留存/付费、已具备 TestFlight/App Store 条件或已具备任何未核验资产/字体授权。
