# 地球Online小向导 App｜项目核心约束

## 核心承诺与当前非目标

- 将用户自有账号 **@地球Online小向导** 的内容机制迁移到 iOS App。
- 保留可核验的视觉世界观与任务节奏：每日任务、特别任务、紧急任务、DLC 式任务、彩蛋任务。
- 明确剔除：用户共创、评论区投稿、公开社区、社交互动、任务审核。
- 当前非目标：账号系统、商城/IAP、云同步、复杂个性化、持续定位、医疗/心理健康功能。
- 账号自有授权不自动覆盖第三方字体、音乐、模板、插件、素材或相邻账号内容。

## 核心任务状态机

首版不设“领取”“完成当天任务”“跳过”或前台换任务。每天按设备当地时间 `05:00` 自动生成 3 个核心任务；彩蛋任务以 25% 的本地确定性概率出现。

- 每个任务项独立处于 `进行中 → 已完成`，用户勾选即完成并记录时间。
- 当个业务日内允许取消勾选并撤销完成；撤销后从用户可见历史中移除。
- 到下一个当地 `05:00`，未完成任务直接结束且不进入用户可见历史；历史只显示已完成任务。
- 未完成任务从下一业务日起立即重新进入候选池；已完成且未撤销的任务在之后 30 个业务日内不得再次出现，冷却结束后重新进入候选池。核心任务和彩蛋任务使用同一规则。
- `DailyPlan` 是当天任务集合的唯一聚合根；它拥有 `DailyInstance`，并冻结业务日、时区、任务包版本和下一次 `05:00` 边界。同一安装同一业务日只能有一个完整 DailyPlan。
- `DailyInstance` 保存不可变 `TaskSnapshot`；历史不得读取会变化的活 TaskCard。
- “换一个”只可保留内部扩展接口，首版的 UI、通知、快捷指令和深链均不得触发。
- 通知只作为提醒与打开 Today 的入口，不是真值源；所有排程、取消、重排程必须幂等。MVP 不做锁屏内联完成、快捷指令完成或 Widget 写入。

## 任务身份与抽取约束

- `canonicalTaskID` 表示跨任务包和文案版本不变的具体任务身份；`taskRevisionID` 表示该任务的一次内容修订；`experienceFamilyKey` 只表示相似体验族，三者不得混用。
- 30 个业务日完成冷却按 `canonicalTaskID` 判断；修改文案或更新任务包不得绕过冷却。
- 最近出现过的 `experienceFamilyKey` 只降低再次抽中的概率，不构成硬排除；未完成任务仍有资格在下一业务日被重新抽中。
- 首版不建立独立 `SelectionLedger`；已展示历史以 DailyPlan/DailyInstance 为真值，完成冷却以未撤销 Completion 为真值。
- TaskPack 进入 App 前必须通过本地 Validator：身份唯一、字段完整、双语、安全/许可、体验族、资源引用、容量和确定性抽取验证任一失败即不得启用。
- 任务内容源必须记录 `contentStatus / safetyStatus / localizationStatus / licenseStatus`；发布包只能包含内容已批准、安全通过、发布双语就绪且许可已核验的任务。开发档可保留英文待补状态，但不得冒充发布就绪。
- Task Selection 的硬约束不可放宽：内容批准、安全、许可、任务类型、明确时间/可用条件、同日 canonicalTaskID 唯一及完成后 30 个业务日冷却。运行时只能依次放宽近期体验族降权和同日体验族分散；仍不足时少展示或报任务包不足，不得使用不合格任务。
- DailyPlan 必须先在内存完成全部选择和完整性校验，再一次显式保存；失败或崩溃后使用同一业务日、同一任务包、同一算法与同一种子重试，不得换种子碰运气。
- `installID` 在用户首次完成本地 ID 设置时生成随机 UUID，仅保存于 SwiftData LocalProfile；重启和升级不变，修改显示 ID 不影响它。清除所有数据或卸载后重装会生成新的 installID；首版不写入 Keychain、UserDefaults 或云端。

## Focumi 可迁移原则

- 单一事实源：领域状态与展示状态分离，展示不能反向证明真实结果。
- 外部系统、通知、快捷指令或 Widget 的显示不代表用户已完成，也不代表系统已成功写入。
- 所有勾选完成、撤销、刷新和通知动作可重复执行而不产生重复记录；优先恢复、重算和审计。
- 离线优先：本地任务包与本机状态可独立完成核心闭环，联网更新不能破坏旧实例。
- 构建通过、测试通过、模拟器截图或 UI 显示都不能替代真机、用户证据或现实任务验证。

## 开发与验收分层

分别记录：实现证据、构建证据、自动化测试证据、模拟器证据、真机证据、用户证据。上一层不得冒充下一层。

- 优先做最小 capability spike：本地通知授权/取消、当地 `05:00` 跨日刷新和离线重启恢复。
- MVP 的通知只用于提醒和打开 App；不承诺精确后台执行，不做锁屏内联完成、快捷指令完成或 Widget 写入。
- 任务完成默认只是用户在 App 内的自报/确认，不夸大为现实行为已被验证；除非另有独立证据，不采集或要求照片、定位等证明。
- UNKNOWN 必须保持 UNKNOWN；不得用旧截图、工具自述或“3/3 pass”替代缺失证据。

## V-S-C-R 后续验证门

- `V`：账号既有内容的传播证据，只能说明触达。
- `S`：安装并打开 App。
- `C`：用户勾选至少一个现实任务为完成（当前只记录用户自报，不代表现实行为已被客观验证）。
- `R`：无提醒情况下第 3/7 日自然回访并复用核心任务闭环。

没有 C/R 证据，不得把互动、点赞、收藏或账号流量解释为 App 留存、需求或付费绿灯；商城、付费 DLC 和增长扩张须等待验证。
